# PLAN.md
## План реализации GoNext — Дневник туриста

Документ описывает **поэтапный порядок действий** по реализации MVP из `PROJECT.md`.
Исходная точка: уже есть минимальное Expo Router + TypeScript + React Native Paper приложение.

---

## Этап 1. Подготовка и каркас

1. Зафиксировать стек MVP: Expo, Expo Router, React Native Paper, SQLite, локальные фото.
2. Привести структуру проекта к рабочему каркасу:
   - `app/` — экраны и маршруты
   - `src/db/` — база и репозитории
   - `src/types/` — типы сущностей
   - `src/services/` — геолокация, карты, файлы фото
   - `src/components/` — переиспользуемые UI-компоненты
3. Настроить базовый `app/_layout.tsx`:
   - `PaperProvider`
   - `SafeAreaProvider`
   - Expo Router `Stack`
4. Подключить необходимые зависимости:
   - SQLite (`expo-sqlite`) и проверить, что модуль успешно подключается
   - выбор/съёмка фото (`expo-image-picker`, `expo-file-system`)
   - открытие карт/навигатора (`expo-linking` / системные URL)
5. Подготовить чистую точку входа: удалить ненужное демо-содержимое экрана Home (без реализации главного экрана GoNext — он делается в Этапе 2).

**Результат этапа:** чистый каркас приложения, готовый к навигации и данным.

---

## Этап 2. Главный экран и навигация

1. Сделать главный экран `GoNext` с вертикальным рядом кнопок:
   - Места
   - Поездки
   - Следующее место
   - Настройки
2. Настроить маршруты Expo Router:
   - `/` — главный экран
   - `/places` — список мест
   - `/places/[id]` — карточка места
   - `/places/new` (или модалка) — создание места
   - `/trips` — список поездок
   - `/trips/[id]` — детали поездки/маршрут
   - `/trips/new` — создание поездки
   - `/next` — следующее место
   - `/settings` — настройки (заглушка MVP)
3. Оформить экраны через React Native Paper (`Appbar`, `Button`, `List`, `FAB`, `TextInput`, `Snackbar` и т.д.).
4. Сохранить простую мобильную навигацию без сложных вложенных меню.

**Результат этапа:** по приложению можно пройтись по всем основным разделам (пока с заглушками).

---

## Этап 3. Модель данных и локальное хранилище

1. Описать TypeScript-типы:
   - `Place`
   - `Trip`
   - `TripPlace`
2. Спроектировать схему SQLite:
   - таблица `places`
   - таблица `trips`
   - таблица `trip_places`
   - таблица `place_photos` (пути к файлам фото мест)
   - таблица `trip_place_photos` (пути к файлам фото посещений)
3. Реализовать инициализацию БД при старте приложения.
4. Сделать репозитории CRUD:
   - места: создать / читать / обновить / удалить / поиск по названию
   - поездки: создать / читать / обновить / удалить
   - места в поездке: добавить / изменить порядок / отметить посещённым / заметки
5. Добавить слой хранения фото:
   - сами файлы фотографий хранятся локально в файловой системе приложения
   - в SQLite (`place_photos`, `trip_place_photos`) хранятся только пути к этим файлам

**Результат этапа:** все данные пишутся и читаются локально, приложение работает офлайн.

---

## Этап 4. Режим «Места»

1. Экран списка мест:
   - вывод сохранённых мест
   - поиск по названию
   - фильтрация по полям `visitlater` и `liked`
   - переход к карточке / созданию
2. Форма создания/редактирования места:
   - `name`, `description`
   - `visitlater`, `liked`
   - координаты `dd` (вручную и/или через текущую геопозицию)
   - прикрепление фотографий
3. Карточка места:
   - просмотр всех полей
   - галерея фото
   - действие «Открыть на карте»
4. Связать UI с репозиторием `places`.

**Результат этапа:** полноценный офлайн-справочник мест.

---

## Этап 5. Режим «Поездки»

1. Экран списка поездок с признаком текущей (`current`).
2. Создание поездки:
   - `title`, `description`
   - `startDate`, `endDate`
   - выбор/добавление мест в маршрут
3. Экран деталей поездки (маршрут):
   - упорядоченный список `TripPlace`
   - изменение порядка мест
   - отметка `visited` + `visitDate`
   - заметки `notes`
   - фото посещения
4. Логика выбора текущей поездки (одна активная).
5. Отображение поездки в двух режимах восприятия:
   - как план (есть непосещённые места)
   - как дневник (посещённые места с заметками/фото)

**Результат этапа:** поездки планируются и ведутся как дневник.

---

## Этап 6. Режим «Следующее место»

1. Реализовать логику:
   - взять поездку с `current = true`
   - найти первое место с `visited = false` по `order`
2. Экран «Следующее место»:
   - название и краткая информация
   - кнопки:
     - открыть на карте
     - открыть в навигаторе (Google Maps / системный)
3. Обработать пустые состояния:
   - нет текущей поездки
   - все места уже посещены

**Результат этапа:** быстрый доступ к следующему пункту маршрута.

---

## Этап 7. Карты, навигатор и геолокация

1. Унифицировать сервис открытия внешних карт по координатам `dd`.
2. Подключить получение текущих координат (для создания места / удобства).
3. Проверить работу без интернета там, где это возможно (локальные данные всегда доступны; внешние карты — best effort).

**Результат этапа:** из приложения удобно перейти к месту на карте или в навигаторе.

---

## Этап 8. Настройки и полировка MVP

1. Экран «Настройки» (минимальный):
   - информация о приложении
   - при необходимости — простые локальные опции (например, очистка данных только после явного подтверждения)
2. Единый визуальный стиль Paper по всем экранам.
3. Обработка ошибок и пустых списков (`Snackbar`, понятные пустые состояния).
4. Базовая проверка сценариев:
   - создать место → найти → открыть на карте
   - создать поездку → добавить места → изменить порядок
   - отметить посещение → появилось следующее место
   - перезапуск приложения → данные сохранились

**Результат этапа:** стабильный офлайн MVP, готовый к использованию на телефоне.

---

## Этап 9. Что сознательно не делаем в MVP

Отложено согласно `PROJECT.md` (раздел 7):
- экспорт поездки в PDF
- резервное копирование
- синхронизация между устройствами
- совместные поездки
- статистика путешествий
- отображение всего маршрута на карте целиком

---

## Порядок выполнения (кратко)

1. Каркас и зависимости  
2. Главный экран + маршруты  
3. SQLite + типы + репозитории + фото  
4. Режим «Места»  
5. Режим «Поездки»  
6. Режим «Следующее место»  
7. Карты/геолокация  
8. Настройки и финальная полировка  

Каждый этап завершается проверяемым результатом; к следующему переходим только после работоспособности предыдущего.
